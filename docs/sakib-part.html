Sakib: Frontend Technical Reference

RoadGuard · client-side architecture, browser APIs, libraries and techniques used · about 40% of the project, plus the live demo

Stack Architecture Networking & auth Real-time Geolocation Leaflet Routing Animation Upload CSS Security Files API contract Viva Q&A Limitations
One-line summary. The frontend is a multi-page application (MPA) written in vanilla JavaScript (ES2017+), HTML5 and CSS3, with Leaflet for maps and STOMP over SockJS for server push. It has no framework, no bundler and no npm dependencies. Spring Boot serves the files from src/main/resources/static/, and the browser talks to the backend through a REST/JSON API plus a WebSocket.

2. Client-side architecture

2.1 Multi-page application, not an SPA

Each role has its own HTML document (driver.html, mechanic.html, admin.html) and navigation is a full page load through window.location.href. There is no client-side router and no virtual DOM. Each page loads only the scripts it needs, in a fixed order, because classic scripts share one global scope:

driver.html lines 91–100 
leaflet.js → sockjs.min.js → stomp.min.js → api.js → live.js → home.js
→ route.js → driver-map.js → sos-radar.js → driver-sos.js

Order matters: sos-radar.js ends with SosRadar.attach(map) and uses the map created in driver-map.js; driver-sos.js calls Live and api.

2.2 Module pattern (IIFE) and a global namespace

Without ES modules, encapsulation is done with an IIFE returning a public API (the revealing module pattern). Private state lives in the closure.

live.js lines 1–8 and 77–89 (shape only) 
const Live = (function () {
    let client = null;          // private
    let connected = false;      // private
    const handlers = [];        // private
    /* ... */
    return { connect, onMessage(handler) { handlers.push(handler); }, isConnected() {...}, subscribeTopic(topic) {...} };
})();

Modules built this way: Live, Route, SosRadar, JobMap, PinPicker, Shop, Skills. driver-map.js instead exposes an object literal on window.RoadGuardMap with setOrigin, showHelper, hideHelper, pinPosition, lockPin, showMechanics, fitHelper. driver-sos.js checks if (window.RoadGuardMap) before calling it, i.e. a defensive dependency check.

2.3 Rendering: template literals into innerHTML

A panel is rebuilt as an HTML string and assigned to innerHTML on every state change (showForm(), showStatus(req), renderOffers(), renderJob(), renderDuty()). This is full re-render, no diffing. It is simple and predictable at this size, and it is why the page needs event delegation (next section). All server-supplied text goes through an escape function before interpolation (see Security).

2.4 Event delegation

Because the panel’s children are destroyed and recreated by innerHTML, listeners attached to them would be lost. A single listener on document catches bubbling events and uses Element.closest() to identify the target.

driver-sos.js lines 334–347 
document.addEventListener('click', (e) => {
    if (e.target.closest('#helper-fit')) { window.RoadGuardMap.fitHelper(); return; }
    if (e.target.closest('#sos-send')) sendSos();
    else if (e.target.closest('#sos-cancel')) cancelSos();
    else if (e.target.closest('#sos-new')) { activeRequest = null; stopPolling(); showForm(); }
});

2.5 State management

There is no store library. Each page keeps a small module-level state object, and the server is the source of truth:

  • Driver: activeRequest (the last ServiceRequestResponse), pollTimer.
  • Mechanic: state = { profile, offers, job, lastPosition, busy } in mechanic-console.js (lines 25–31; state.pin is assigned later when the map is set up). refresh() refetches profile, current job and offers, then calls renderDuty(), renderJob(), renderOffers().

Every WebSocket message of kind STATUS simply triggers a refetch (poll() / refresh()), so the UI never has to merge partial updates.

3. Networking and authentication

3.1 The api() wrapper over the Fetch API

api.js lines 36–62 
async function api(path, options = {}) {
    const headers = { 'Content-Type': 'application/json', ...(options.headers || {}) };
    const token = Auth.token();
    if (token) headers['Authorization'] = 'Bearer ' + token;

    const res = await fetch(path, { ...options, headers });
    if (res.status === 204) return null;            // No Content

    let body = null;
    const text = await res.text();
    if (text) { try { body = JSON.parse(text); } catch { body = { message: text }; } }

    if (!res.ok) throw new Error((body && body.message) || `Request failed (${res.status})`);
    return body;
}
  • Attaches the JWT as a Bearer token in the Authorization header.
  • Handles 204 No Content explicitly, reads the body as text first and then parses, so a non-JSON error body does not crash res.json().
  • Normalises errors: a non-2xx response becomes a thrown Error(message) using the server’s message field, so callers use a single try/catch.

3.2 Token storage and route guard

  • Token and user (userId, username, role) are stored in localStorage under roadguard.token and roadguard.user.
  • requireLogin(expectedRole) calls GET /api/auth/me; on 401 or a role mismatch it clears storage or redirects with Auth.homePage(role).
  • This guard is a usability redirect, not security. Authorisation is enforced by the server (Spring Security with a JWT filter).
Trade-off to state. A token in localStorage is readable by any script on the page, so an XSS bug could steal it. An HttpOnly cookie avoids that but needs CSRF protection. This project chose localStorage with a stateless JWT. If asked, say you know the trade-off.

3.3 Why photo upload bypasses api()

api() forces Content-Type: application/json. A multipart upload must not set that header manually, because the browser has to generate the multipart/form-data; boundary=... value itself. So sendPhoto() calls fetch directly with a FormData body and only the Authorization header (sendPhoto, driver-sos.js from line 191).

3.4 Fetching a protected image: fetch → Blob → object URL

An <img src> cannot send an Authorization header, and the SOS photo is private. So the page fetches the bytes with the header, converts the response to a Blob and gives the image an object URL. Promise.all loads all offer photos concurrently.

mechanic-console.js lines 245–266 
const response = await fetch(placeholder.dataset.photoUrl, { headers: { Authorization: 'Bearer ' + token } });
if (!response.ok) throw new Error('Photo request failed');
const image = document.createElement('img');
image.src = URL.createObjectURL(await response.blob());
placeholder.replaceWith(image);

3.5 Cross-origin requests

route.js and pin-picker.js call OSRM and Nominatim directly from the browser, so these are cross-origin (CORS) fetches to third-party servers; they work because those services allow it. They carry no JWT (the code does not add one), which is correct for third-party hosts.

live.js (89 lines) implements a publish/subscribe client on top of WebSocket, with SockJS as the transport that falls back to HTTP streaming or long polling if a WebSocket is blocked.

Push plus polling (hybrid)

The server uses Spring’s simple in-memory broker (enableSimpleBroker("/topic", "/queue")). It does not store or replay messages, so a client that was disconnected misses them. That is why the pages also poll: it gives eventual consistency even if a push is lost.

Filtering raw fixes (mechanic-console.js lines 62–108 (onFix starts at 79))

const WORST_ACCURACY_M = 120;   // coords.accuracy is in metres
const JITTER_KM = 0.015;        // 15 m

function onFix(pos) {
    const accuracy = pos.coords.accuracy;
    if (accuracy > WORST_ACCURACY_M) { /* show "Weak signal", keep last position */ return; }
    const moved = state.lastPosition ? Route.haversineKm(state.lastPosition, next) : Infinity;
    if (moved < JITTER_KM) { return; }                 // below the noise floor: do not update or upload
    state.lastPosition = next;
    saveMyLocation(next.lat, next.lng);                  // POST /api/mechanic/location
}
  • Accuracy gate (> 120 m rejected) plus a dead-band / distance threshold (< 15 m ignored) so a stationary phone does not generate a stream of tiny movements.
  • Error handling: err.code === 1 is PERMISSION_DENIED and the page tells the mechanic to place the pin by hand; other errors say there is no fix yet.
  • Secure context: window.isSecureContext is checked because browsers expose geolocation only on HTTPS or localhost.
  • Distance uses the Haversine formula with Earth radius R = 6371.0088 km (route.js, using Math.sin, Math.cos, Math.asin). The same formula also exists in Java as GeoUtils on the server.

If the panel is wider than 70% of the viewport (phone layout) it pads the bottom by the panel height; otherwise it pads the left by the panel’s right edge.

7. Routing client and graceful degradation

route.js lines 1–53 
const url = OSRM + from.lng + ',' + from.lat + ';' + to.lng + ',' + to.lat
          + '?overview=full&geometries=geojson&alternatives=false&steps=false';
const data = await (await fetch(url, { headers: { Accept: 'application/json' } })).json();
const best = data.routes[0];
return { line: best.geometry.coordinates.map((c) => [c[1], c[0]]),
         km: best.distance / 1000, minutes: best.duration / 60, onRoads: true };
/* catch: */ return straightLine(from, to);   // Haversine distance, minutes = km / 22 * 60, onRoads: false
  • OSRM returns distance in metres and duration in seconds; the code converts to km and minutes.
  • overview=full&geometries=geojson asks for the complete route as GeoJSON coordinates.
  • Graceful degradation: any failure (network, non-2xx, empty route) falls back to a straight line with CITY_KMH = 22. The UI reads onRoads to dash the line and change the label (“direct line”) so it never presents an estimate as a road route.

9. Client-side file handling (SOS photo and shop image)

  1. <input type="file" accept="image/jpeg,image/png,image/webp" capture="environment" hidden>. accept filters the picker; capture="environment" asks phones for the rear camera.
  2. On change: validate file.size > 5 * 1024 * 1024, show a toast and reset e.target.value = '' if too large.
  3. Preview with FileReader.readAsDataURL, assigned to style.backgroundImage of a preview element (base64 data URL).
  4. Upload with FormData.append('file', photo) and fetch(..., { method: 'POST', body: form }).
  5. Failure path: a non-OK response shows a toast and the page reloads the request with GET /api/requests/{id}, so the SOS continues without the photo.

Two-step protocol: POST /api/requests with hasPhoto: true first (server sets DIAGNOSING), then POST /api/requests/{id}/photo. The driver’s status panel renders the returned diagnosis (aiFaultCategory, severity, aiGuidance) in a “Photo check” block when present.

14. Viva questions, answered in technical terms

Why polling and WebSocket?

WebSocket push gives low latency, but the broker is Spring’s in-memory simple broker with no replay, so a disconnected client misses messages. The 15 s poll guarantees eventual consistency. Push is the fast path, polling is the correctness path.

Why one document click listener instead of per-button listeners?

Event delegation. The panel is regenerated through innerHTML, which destroys child nodes and their listeners. A delegated listener on document survives re-renders, and closest() resolves which button was clicked.

Why no React or other framework?

Scope: a handful of screens with simple state, so template literals plus innerHTML are enough and there is no build step. The cost is manual DOM updates, full re-render on change, and duplicated helpers. For a bigger product a component framework would be justified.

Why L.circle and not L.circleMarker?

L.circle takes its radius in metres and is projected geodesically, so a 5 km search area is 5 km on the ground at any zoom. circleMarker has a pixel radius that does not scale with zoom.

Why divIcon markers?

They render as HTML/CSS, so colour, size and animation (the pulsing mechanic marker) come from the stylesheet and no image assets are needed.

What is the longitude/latitude order problem?

GeoJSON and OSRM use [lng, lat], Leaflet uses [lat, lng]. route.js swaps at both boundaries: building the URL and mapping the returned geometry.

Throttling versus debouncing: which did you use?

Throttling (time/distance based): the route is refetched at most every 25 s or after 80/150 m of movement. Place search uses a minimum-interval rate limit (1.1 s) plus AbortController cancellation. It is not a debounce, because the search is triggered by an explicit action, not by keystrokes.

How do you stop a double click on Accept?

A state.busy guard returns early, and the button is disabled and replaced with a spinner while the request is in flight. The server also decides the winner, so even a duplicate would not create two assignments.

Why fetch the photo as a Blob?

An <img> request cannot carry an Authorization header and the photo is private. fetch with the header, then response.blob() and URL.createObjectURL.

Why does multipart upload not use your api() helper?

The helper sets Content-Type: application/json. For FormData the browser must set multipart/form-data with its own boundary, so the header must be left unset.

How does the GPS filter work?

Accuracy gate (reject fixes with coords.accuracy over 120 m) plus a 15 m dead-band using Haversine distance from the last accepted fix. Only accepted fixes update the map and are POSTed.

What happens if OSRM is down?

The try/catch in Route.between returns straightLine() with onRoads: false; the polyline is dashed and the label says “direct line”.

Is storing the JWT in localStorage safe?

It is exposed to any injected script, so it relies on XSS prevention (escaping). The alternative is an HttpOnly, SameSite cookie plus CSRF protection. State the trade-off and that the choice was made for a stateless API.

Can a user bypass the client-side role check?

Yes, the redirect is only convenience. The backend (Spring Security + JWT filter, Ifty’s part) rejects unauthorised calls.

15. Known limitations (say these before they are found)

  • Memory: URL.createObjectURL is never paired with revokeObjectURL (0 uses), so each loaded photo keeps its blob until the page unloads.
  • Reconnect: fixed 3 s retry, no exponential back-off or jitter.
  • No build pipeline: no bundling, minification, ES modules or linting; global scope shared across scripts.
  • No automated frontend tests: src/test contains only Java tests.
  • Duplication: three copies of an HTML-escape helper, two Haversine implementations (JS and Java), and inconsistent route-refetch thresholds (80 m vs 150 m).
  • Accessibility: aria-* attributes are absent from driver.html and mechanic.html (0 occurrences); not audited with a screen reader.
  • No dark mode in the stylesheets.
  • Network dependency: Leaflet, SockJS, STOMP and fonts load from CDNs and tiles from OSM. With no internet the map and the live connection do not load at all.
  • Browser limit: no background geolocation; the page only reports position while it is open and active.
  • Admin UI is a placeholder.
